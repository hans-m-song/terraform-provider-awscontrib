### Decisions

- Plan a small, service-oriented modular monolith with `internal/provider`, `internal/conns`, and `internal/service/<aws-service>` boundaries.
- Use `terraform-provider-aws` as the primary precedent for AWS SDK v2 integration and service ownership.
- Use `terraform-provider-awscc` only as a secondary Plugin Framework precedent; do not adopt Cloud Control generation.
- Start with explicit registration and narrow service client interfaces.
- Defer shared helper packages until at least two consumers demonstrate a stable abstraction.
- The first planned capability is a plural Amazon Connect quick-connect data source backed by `ListQuickConnects`.
- The quick-connect data source must exhaust API pagination unless its approved Terraform contract explicitly exposes pagination.
- A queue/quick-connect association resource was initially removed, then restored as milestone `M1` on 2026-08-18 after analysis showed it avoids data-source-driven two-apply convergence.
- Quick-connect discovery remains milestone `M2`.

### Owner decisions canonicalized on 2026-08-18

- Use Terraform type name `awscontrib` and Go module `github.com/hans-m-song/terraform-provider-awscontrib`.

- Minimum AWS authentication scope is standard shared INI configuration/credentials support plus explicit profile selection.
- Represent plural quick-connect results as a predictably ordered list sorted by quick-connect ID.
- Require item `id`; expose other `ListQuickConnects` summary attributes when practical.
- Use only `ListQuickConnects` initially. Support API-exposed quick-connect-type filters and exact client-side name filtering after complete pagination.
- No stable real-AWS fixtures will be provided. Repeatable mocked and Framework tests are the required gate; any real-AWS smoke test is supplementary and separately authorized.
- Choose the most well-supported maintained AWS configuration integration at implementation time. Prefer stable AWS SDK for Go v2 APIs; use a HashiCorp helper only if its current support evidence is stronger.
- Follow current Terraform conventions for remaining schema choices: required string `instance_id`, optional string `name`, optional enum-validated set `quick_connect_types`, and computed list nested attribute `quick_connects` sorted by item ID.
- Omit a synthetic data-source-level `id` because the query has no remote identity and current Framework testing does not require one. Require the real AWS `id` within every returned quick-connect item.
- Expose all summary fields returned by `ListQuickConnects` as computed attributes: ID, ARN, name, type, last-modified region, and last-modified time.
- Model one queue/quick-connect association edge per Terraform resource. Serialize mutations per `{instance_id, queue_id}` within the provider process, reconcile through paginated membership reads, and document that cross-process concurrency is not guaranteed by AWS.

### Corrections and lessons

- Amazon Connect documents queue/quick-connect associations, not routing-profile/quick-connect associations. Routing profiles expose queues to agents; queues hold quick-connect associations.
- `ListQuickConnects` returns summaries. Full description and nested configuration require `DescribeQuickConnect`; adding per-item describe calls would materially change performance, permissions, throttling, and schema and therefore requires an explicit decision.
- `ListQuickConnects` does not expose a name parameter. Name filtering must be client-side if the implementation remains list-only; `SearchQuickConnects` is a distinct API and contract.
- Terraform lists preserve order, sets represent unordered unique values, and new Framework schemas should prefer nested attributes to blocks. These semantics drive the selected result and filter types.
- The existing HashiCorp AWS provider already exposes a singular `aws_connect_quick_connect` data source. The planned contribution is plural discovery rather than another singular lookup.

### Rejected approaches

- Copying the full `terraform-provider-aws` helper, generator, and SDKv2/Framework mux architecture: disproportionate to the repository's intended size.
- Using the AWS Cloud Control provider's generated-resource model: the initial capability uses a direct Amazon Connect list API.
- Encoding an incorrectly named routing-profile/quick-connect association resource.

## 2026-08-18 — Provider bootstrap and association resource

### Implemented

- Renamed the module to `github.com/hans-m-song/terraform-provider-awscontrib`, provider type to `awscontrib`, and server address to `registry.terraform.io/hans-m-song/awscontrib`.
- Set both Go modules to Go 1.26 and retained Terraform protocol 6 compatibility with Terraform 1.0+.

- Removed accidental scaffold resources, data sources, actions, functions, ephemeral resources, examples, and generated reference pages.
- Replaced template documentation, examples, catalog metadata, and generator naming with `awscontrib` content.
- Removed IBM-specific Copywrite automation so new project files are not assigned an incorrect copyright holder. Existing template notices remain where inherited.

### Association lifecycle

- One Terraform resource owns one `{instance_id, queue_id, quick_connect_id}` edge.
- All identity attributes are required and replacement-only.
- Create performs a membership pre-read, calls `AssociateQueueQuickConnects` when absent, and reconciles membership.
- Read exhausts `ListQueueQuickConnects` pagination and removes state when membership or the parent queue/instance is absent.
- Delete performs a membership pre-read, calls `DisassociateQueueQuickConnects` when present, tolerates concurrent not-found, and reconciles absence.
- Import format is `instance_id,queue_id,quick_connect_id`.
- Mutations serialize by `{instance_id, queue_id}` through a coordinator shared by resources created from one provider instance. Independent queues remain parallel.
- Reconciliation makes five observations with cancellation-aware waits of 250, 500, 750, and 1000 milliseconds. Only membership mismatch, typed internal-service errors, and throttling errors retry.

### Verified

- Focused race tests cover concurrency, reconciliation, not-found, pagination, import parsing, and transient/permanent errors.
- Provider tests cover profile/region mapping, configured data propagation, registration, and loader diagnostics.
- `go test ./...`, `go build ./...`, `make lint`, and two documentation generations passed.
- No real AWS calls were made because no stable fixture exists.

### Residual risks

- Queue locking is process-local. Multiple Terraform processes or states must not own the same association edge.
- AWS does not document concurrent-mutation isolation for these APIs.
- The 2.5-second reconciliation window is evidence-free until exercised against real Amazon Connect behavior and may require future tuning.

## 2026-08-19 — Plural queue quick-connect associations

### Evidence and correction

- A real provider run returned HTTP 429 `TooManyRequestsException` from `AssociateQueueQuickConnects` after the AWS SDK exhausted its default three attempts.
- The owner chose request reduction through batching and explicitly declined provider-level `max_retries` and `retry_mode` configuration. Provider configuration therefore remains limited to `profile` and `region`; standard AWS SDK and shared-configuration retry controls remain external.
- Amazon Connect accepts 1 through 50 quick-connect IDs per associate request. The resource does not impose 50 as a total set limit; it chunks larger declared sets into requests of at most 50 IDs.

### Superseding association contract

- Before the first published release, replaced `awscontrib_connect_queue_quick_connect_association` with `awscontrib_connect_queue_quick_connect_associations`.
- The resource requires an unordered, nonempty `quick_connect_ids` set and owns only that declared additive subset. Create associates missing declared IDs, read retains the intersection of declared and remote membership, and delete removes only declared IDs that remain present.
- Unrelated queue associations are preserved. Overlapping ownership of the same edge across resource instances or Terraform states is unsupported.
- Import uses `instance_id:queue_id:quick_connect_id[,quick_connect_id...]`. Every component must be a UUID; duplicate quick-connect IDs are rejected and IDs are sorted before state import.
- Provider-local `{instance_id, queue_id}` mutation serialization remains. Reconciliation now also treats the SDK's typed `TooManyRequestsException` as transient, without changing the SDK mutation retry budget.

### Verification

- Deterministic tests cover associate and disassociate chunking beyond 50 IDs, empty and invalid set validation, subset preservation, partial and total drift, pagination, canonical import, transient reconciliation, and queue-local concurrency.
- Full unit tests, focused race tests, build, lint, and generated documentation passed. Two consecutive generations produced identical reference checksums. Independent testing found no release blocker. No real AWS calls were made during verification.

## 2026-08-19 — Approved Connect lifecycle expansion

### Queue association updates

- The owner approved changing `quick_connect_ids` in place while retaining replacement semantics for `instance_id` and `queue_id`.
- Update reconciliation compares prior ownership, planned ownership, and complete remote membership under the existing `{instance_id, queue_id}` coordinator.
- Removed owned IDs are processed before additions. This reduces the risk of an add-first failure when the queue is at its association quota, but a failed apply can temporarily remove an old association before its replacement is added.
- AWS mutations are not treated as a transaction. Successful earlier batches are not rolled back after a later failure; state is not advanced, refresh exposes remote completion, and a subsequent apply reconciles the remainder.

### Exact lookup data sources

- `awscontrib_connect_phone_number` uses paginated `ListPhoneNumbersV2`, a conservative server prefix of at most 11 total characters, and exact full-number comparison client-side. Zero and multiple exact matches are errors.
- `awscontrib_connect_contact_flow_module` uses paginated `SearchContactFlowModules`, sends a `CONTAINS` criterion only when the configured name satisfies the documented 2–25-character constraint, and always enforces exact equality client-side. A separate contact-flow data source is omitted because the HashiCorp AWS provider already supplies one.
- The pinned Connect SDK `v1.189.0` returns full contact-flow-module objects from search. External invocation configuration is deliberately outside the initial Terraform schema; requested content, hash, settings, state, status, version metadata, and tags are included.

### Hours and data-table boundaries

- Hours-of-operation overrides will be standalone resources rather than nested state. This maps to the dedicated create, describe, update, and delete API family and permits explicit attribute-removal behavior.
- Data-table metadata and its complete provider-managed attribute set are one authoritative resource. DEFAULT values are an explicit map keyed by attribute name; non-default records remain separate resources keyed by a nonempty, canonical composite primary-value map.
- The owner's real CLI observations on 2026-08-19 establish that omitting `PrimaryValues` from `BatchCreateDataTableValue` creates a concrete value with `RecordId` `DEFAULT`, including after an ordinary record exists. `ListDataTablePrimaryValues` does not return that DEFAULT record, while `ListDataTableValues` returns explicit DEFAULT values.
- The console may render an implicit empty Default row when no explicit DEFAULT values exist. Provider state must reflect stored API values rather than adopting that presentation-only row.
- The pinned SDK exposes no record CRUD API. Ordinary records are composed from batch value operations; composite primary values are represented as a sorted API slice and a Terraform map.
- The pinned SDK's `DataTableStatus` currently exposes only `PUBLISHED`, despite inconsistent generated prose mentioning `SAVED`. `SAVED` remains excluded until primary documentation or real-service evidence resolves the contradiction.

## 2026-08-19 — Direct Connect data-table lifecycle

- Implemented `awscontrib_connect_data_table` as the authoritative owner of table metadata, the complete set of attributes represented by the provider schema, and explicit DEFAULT values.
- Attribute maps are keyed by remote attribute name. Removing a key deletes the attribute and its values; renaming is therefore delete/create. Primary-to-non-primary demotion replaces the table because the pinned SDK omits `Primary:false`.
- DEFAULT values are created, updated, and deleted through batch value APIs with `PrimaryValues` omitted. Reads paginate all values and retain only concrete `RecordId` `DEFAULT` cells.
- Table create persists returned identity before child mutations so partial attribute/default failures remain recoverable. Later failed update batches do not advance planned state. Repeated pagination tokens and unsupported remote statuses are errors.
- Implemented `awscontrib_connect_data_table_record` for non-default records. Composite primary maps are nonempty and converted to a lexicographically sorted API slice; primary changes replace the resource.
- Record reads first resolve an exact composite key through paginated primary values, then read every cell for the resolved record ID. The `values` map is authoritative over the complete record, so remote additions enter state as drift.
- Batch create, update, and delete validate that every requested attribute is classified exactly once as success or failure and that returned primary values and record identity are consistent. Partial successful creates retain only unambiguous recoverable state; no automatic rollback occurs.
- Table and record constructors created by one provider instance share a `{instance_id, data_table_id}` coordinator. Independent tables remain parallel; cross-process serialization is not claimed.
- Tags and AWS attribute validation rules are deferred. Data-table tag mutation support is not documented, and the pinned SDK cannot reliably represent removal of multiple false/zero validation fields.
- Parent verification passed full tests, focused race tests, build, lint, and two genuine Terraform 1.14.0 documentation generations. No real AWS calls were made.

## 2026-08-20 — Hours override time-window DX

- Before publication, replaced the API-shaped `config` collection and nested `{hours, minutes}` objects with optional `time_windows` entries containing required `day`, `opens`, and `closes` attributes.
- Opening and closing times use strict, zero-padded `HH:MM` strings from `00:00` through `23:59`. The provider deliberately does not impose opening-before-closing or overlap rules because AWS midnight and interval semantics do not justify those assumptions.
- `time_windows` is optional and computed with a typed empty-set default. Omission and `[]` are identical in Terraform state and both serialize to a non-nil empty AWS `Config` slice, including when the final window is removed during update.
- `STANDARD` and `CLOSED` accept no windows. `OPEN` requires at least one known window. Day remains explicit and is never inferred.
- Focused and full tests, race tests, lint, schema validation, and two Terraform 1.14.0 documentation generations passed. No real AWS calls were made.

## 2026-08-21 — Connect request-efficiency hardening

- AWS documents Amazon Connect API throttling per operation, shared by account and Region. Most Connect service operations have a steady rate of 2 requests per second and burst 5; actual account quotas can differ.
- One configured provider process now caches one Connect SDK client. A Smithy Finalize middleware inserted immediately after the pinned SDK's `Retry` middleware schedules every physical attempt, including retries, at one attempt per operation every 500 milliseconds with burst 1.
- A process-wide semaphore permits at most two Connect attempts in flight. Operation pacing occurs before semaphore acquisition so queued attempts for one API cannot consume both slots and starve an independent API. Scheduler waits honor context cancellation and use no background goroutines.
- Scheduling is deliberately process-local and best-effort. Provider aliases in independent processes, simultaneous Terraform runs, other providers, CLI commands, and external applications do not share it; no account-wide quota guarantee is claimed.
- All current paginators now use explicit documented-safe page sizes. Data-table refresh filters `ListDataTableValues` to `RecordIds: ["DEFAULT"]`; record reads retain record-ID filters; queue pagination now rejects repeated tokens.
- Data-table update skips unchanged metadata mutations and avoids the intermediate lock-refresh snapshot when DEFAULT values are unchanged. Correctness reads, lock-version refreshes for changed defaults, authoritative final refresh, batching, and drift semantics remain intact.
- Full unit tests passed with Connect coverage 81.4%, connections coverage 87.3%, and provider coverage 95.7%. Focused race tests, build, lint, two Terraform 1.14.0 documentation generations, and diff checks passed. No real AWS calls were made.
- A proposed `M8` records the request to expose resource names. Hours overrides and data tables already expose AWS names; queue association edges and data-table records have no intrinsic AWS resource name, so contract clarification is required before implementation.
- The owner subsequently confirmed that `M8` `name` means the AWS remote object's name when applicable. Terraform block labels, parent-resource names, and synthetic names are excluded. Hours overrides and data tables already qualify; queue association edges and data-table records remain unnamed because those managed remote objects have no intrinsic AWS name.
- Closed `M8` without source changes. The applicable AWS remote names were already exposed, and adding a queue name to an association set or primary values as a record name would misrepresent parent or identity data as the managed object's name.
